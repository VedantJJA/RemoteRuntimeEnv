Architecture and Technical Reference

Remote Runtime Environment (RRE)

A deterministic, resource-bounded sandbox and ranking engine for competitive programming tournaments.

1. System Architecture and Data Flow

RRE is designed around an asynchronous ingestion pipeline backed by an in-memory worker pool orchestrating disposable container sandboxes.

Enforce Limits| Guard[Context Timeout and Cgroups] end Engine -->|10. Capture Metrics| Worker Worker -->|11. Upsert Result| DB Client -->|12. GET /api/result and /api/leaderboard| API

Step-by-Step Lifecycle

  1. Ingestion: Client sends POST /api/submit with problem identifier, language name, code payload, test stdin, and resource limits.
  2. Pre-Registration: API validates schema, records a PENDING row into SQLite, and returns a unique submission ID immediately.
  3. Worker Dispatch: The submission job is pushed to a bounded channel. An idle worker goroutine retrieves the job.
  4. Sandbox Creation: The worker invokes the Docker API to create a brand-new container with read-only rootfs, unshared network namespace, and strict memory/PID cgroups.
  5. Source Streaming: Source code is transferred directly into an in-memory tmpfs scratchpad at /sandbox. Compilation and execution run with real-time timeout supervision.
  6. Persistence: Exit status, wall time, stdout, and stderr are saved back to SQLite, queryable via GET /api/result and GET /api/leaderboard.

Running untrusted code requires defense-in-depth at every layer of the operating system.

3. Code Quality and Extensibility

The system is organized into modular packages following standard Go conventions:

Package Layout
  • internal/api: HTTP routing, JSON marshaling, and REST handlers.
  • internal/queue: Worker pool orchestration and bounded channels.
  • internal/runner: Docker SDK execution and cgroup enforcement.
  • internal/db: SQLite connection pooling, migrations, and queries.
Declarative Language Matrix

Adding support for a new language runtime requires defining its descriptor in languages.go: 

"rust": {
    Name:       "rust",
    Image:      "rre-rust:latest",
    SourceFile: "main.rs",
    CompileCmd: []string{"rustc", "-O", "main.rs", "-o", "main"},
    RunCmd:     []string{"./main"},
}

4. Scalability, Database Optimization, and Cost Efficiency

CPU-Bounded Worker Pool

Rather than spawning unbounded goroutines that risk host crashes under bursts, RRE sizes its worker pool strictly to the host's logical CPU cores (runtime.NumCPU()). Extra submissions wait in a bounded queue (depth = 100), ensuring the system degrades gracefully with predictable latency rather than failing catastrophically.

Efficiency Rule

1 Container per Logical Core = Zero CPU context thrashing + deterministic execution times.

Database Optimization: Pure-Go SQLite

  • In-Process Speed: Eliminates external network roundtrips, delivering sub-millisecond query execution.
  • Composite Indexing: Queries filtering by problem and sorting by wall time are accelerated using: 
    CREATE INDEX IF NOT EXISTS idx_problem_leaderboard ON submissions(problem_id, verdict, wall_time_ms);
  • Lock-Free Reads (WAL Mode): Write-Ahead Logging allows concurrent reads while background workers write results.

5. Reproducibility and Cloud Deployment

RRE provides two production deployment models for fully reproducible environments:

Cloud Container Platform

Runs as a containerized service with Docker-in-Docker (DinD) enabled in deployment manifest:

version: 1
runtime: docker
preset: dockerfile
security:
  privileged: true
Linux Virtual Machine

Native execution on a Linux VM using the provided systemd service definition:

sudo cp deploy/rre.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now rre

6. Tech Stack Justifications

Technology Role Architectural Justification
Go (Golang 1.22+) Backend Core Low memory footprint (~15MB RSS), single static binary compilation, native goroutines for non-blocking worker pools.
Docker Engine API Sandbox Engine First-class Linux kernel cgroups, disposable read-only filesystems, and strict network namespace isolation.
Pure-Go SQLite (modernc) Database Zero external infrastructure cost, zero operations overhead, and CGO-free static compilation across CPU architectures.
Alpine Linux Container Base Minimal attack surface (<10MB image size), fast container initialization.
