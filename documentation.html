1. System Architecture & Data Flow

RRE is structured around a non-blocking ingestion layer backed by an in-memory worker pool that orchestrates isolated, single-use container sandboxes.

Step-by-Step Data Flow

  1. Ingestion: Client sends POST /api/submit with problem ID, language, source code, test stdin, and custom time/memory limits.
  2. Pre-Registration: API validates input constraints, immediately saves a PENDING row into SQLite, and returns a unique UUIDv4 to the client in under 5ms.
  3. Worker Dispatch: The submission is pushed into a bounded Go channel queue. A free worker goroutine pulls the job.
  4. Sandbox Spawning: The worker programmatically invokes the Docker API to create a brand-new, isolated container with read-only rootfs, unshared network namespace, and strict memory/PID cgroups.
  5. Source Streaming & Execution: Source code is transferred into an in-memory tmpfs scratchpad at /sandbox. Compilation and execution run with real-time timeout supervision.
  6. Telemetry & Persistence: Exit status, wall time, stdout, and stderr are captured and written back to SQLite, instantly available via GET /api/result and GET /api/leaderboard.

Running untrusted, participant-submitted code requires defense-in-depth at every layer of the operating system.

3. Code Quality & Extensibility

The system is organized into decoupled, modular packages following Go best practices:

📦 Package Layout
  • internal/api: HTTP routing, JSON marshaling, and REST handlers.
  • internal/queue: Worker pool orchestration and bounded channel management.
  • internal/runner: Docker SDK execution, stream handling, and cgroup enforcement.
  • internal/db: SQLite connection pooling, migrations, and indexed queries.
🧩 Declarative Language Matrix

Adding support for a new language requires only defining its execution schema in languages.go:

"rust": {
    Name:       "rust",
    Image:      "rre-rust:latest",
    SourceFile: "main.rs",
    CompileCmd: []string{"rustc", "-O", "main.rs", "-o", "main"},
    RunCmd:     []string{"./main"},
}

4. Scalability, Database Optimization & Cost Efficiency

CPU-Bounded Worker Pool & Graceful Backpressure

Rather than spawning unbounded goroutines that would crash under traffic spikes, RRE sizes its worker pool strictly to the host's available physical CPU cores (runtime.NumCPU()). Extra submissions wait in a bounded queue (depth = 100), ensuring the system degrades gracefully with higher latency instead of crashing or encountering OOM under load.

⚡ Performance Principle

1 Container per CPU Core = Zero CPU context thrashing + 100% deterministic wall-time measurements.

Database Optimization: Zero-Cost, Pure-Go SQLite

  • In-Process Speed: Eliminates external network hops, delivering sub-millisecond query execution.
  • Composite Indexing: The query WHERE problem_id = ? AND verdict = 'ACCEPTED' ORDER BY wall_time_ms ASC is optimized using: 
    CREATE INDEX IF NOT EXISTS idx_problem_leaderboard ON submissions(problem_id, verdict, wall_time_ms);
  • Lock-Free Reads (WAL Mode): Write-Ahead Logging allows simultaneous background worker writes and real-time client leaderboard reads without blocking.

5. Reproducibility & Cloud Deployment

RRE provides two production deployment models for 100% reproducible environments:

☁️ Cloud PaaS (e.g., klouds.online)

Runs as a containerized service with Docker-in-Docker (DinD) enabled in klouds.yaml:

version: 1
runtime: docker
preset: dockerfile
security:
  privileged: true
🖥️ Linux Virtual Machine (systemd)

Native execution on Ubuntu/Debian/Oracle Linux VM using the provided service definition:

sudo cp deploy/rre.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now rre

6. Tech Stack & Architectural Justifications

Technology Role Why It Was Selected
Go (Golang 1.22+) Backend Core Ultra-low memory footprint (~15MB RSS), single static binary compilation, native goroutines for non-blocking worker pools.
Docker Engine API Sandbox Engine First-class Linux kernel cgroups, disposable read-only filesystems, and foolproof network namespace isolation.
Pure-Go SQLite (modernc) Database Zero external infrastructure cost, zero ops, and CGO-free static compilation across all CPU architectures.
Alpine Linux Container Base Minimal attack surface (<10MB image size), near-instant container initialization (<100ms cold start).
